## 04-domain-discovery.md

## 1. Метаданные
| Поле                 | Значение                                              |
| -------------------- | ----------------------------------------------------- |
| Дата                 | 2026-11-01                                            |
| Техника ATT&CK       | T1087                                                 |
| Подтехника           | T1087.001 (Local account), T1087.002 (Domain account) |
| Тактика              | Account Discovery                                     |
| Инструмент атаки     | cmd.exe                                               |
| Источник (атакующий) | win-cl01 (10.10.10.101), Windows 11                   |

## 3. Обнаружение (Detection)
- **rule.id 92039** (level 3) — использование команды net.exe было обнаружено системой, с низким уровнем T1087 Discovery
- **rule.id 92031** (level 3) — Активность подходящая под Discovery T1087, общее правило, которое записало не все команды
- **rule.id 67027** (level 3) — Создание процесса в системе, минимальный алерт без особых техник

## 4. Реагирование (Response)
- Active Response не настраивался для данной атаки: решение принято с учётом опыта разбора №1 (SSH), где Active Response не сработал из-за предполагаемого дефекта в Wazuh 4.14.9-rc2.

## 5. Оценка (Verdict)
**True Positive.** Система нашла несколько команд, но не выставила высокий уровень угрозы и не смогла классифицировать часть команд как попытка Discovery.

## 6. Находки (Findings)
- Правило 67027 слишком общее и без достаточного анализа из него тяжело получить информацию
- Специфичное детектирование T1087 есть только для net.exe (правила 92039, 92031). Команды nltest, systeminfo, ipconfig логируются (rule.id 67027), но это базовая фиксация создания процесса без MITRE-атрибуции — то есть реальный detection gap: аналитик увидит факт запуска процесса, но не поймёт по алерту, что это разведывательная активность, без самостоятельного анализа командной строки
- Ни одно правило не учитывает контекст "разведка сразу после успешного входа с признаками brute-force" — отсутствует корреляционное правило, связывающее разборы №1-2 (Credential Access) с этим разбором (Discovery), хотя такая цепочка — классический (IoC) индикатор компрометации

## 7. Рекомендации
- Расширить набор команд, покрываемых специфичными discovery-правилами (nltest, systeminfo, ipconfig, whoami /all), а не полагаться только на общее логирование процессов
- Добавить корреляционное правило: разведывательная активность (T1087) в течение N минут после успешного входа, которому предшествовали множественные неудачные попытки (как в разборах №1-2) — повышать level такой цепочки событий значительно выше базового level 3
- Рассмотреть использование AD-инструментов аудита (например, ограничение возможности перечисления участников привилегированных групп для непривилегированных пользователей) как дополнительный уровень защиты, а не только детектирования
