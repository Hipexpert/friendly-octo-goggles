# 03-false-positive-powershell-policy-test.md

## 1. Метаданные
| Поле        | Значение                      |
| ----------- | ----------------------------- |
| Дата        | 2026-11-01                    |
| Тип разбора | False Positive Analysis       |
| Хост        | WIN-SRV-22 (DC)               |
| Триггер     | Обычный запуск powershell.exe |

## 3. Обнаружение
- rule.id 92213 (level 15, критический!) и rule.id 92217 (level 6, ~60 алертов) 
  сработали на создание файла __PSScriptPolicyTest_*.ps1 в 
  %LOCALAPPDATA%\Temp\, который PowerShell создаёт автоматически при 
  каждом запуске для проверки execution policy
- MITRE-метка T1105 (Ingress Tool Transfer) неверна для данного случая

## 5. Оценка
**False Positive.** Подтверждено: файл — легитимный системный артефакт 
PowerShell, не связан с загрузкой инструментов атакующего.

## 6. Находки
- Правило 92213/92217 слишком широкое: любой файл в Temp классифицируется 
  как вредоносный дроппер без учёта известных системных паттернов имён файлов
- Критичность level 15 (максимальная) для такого грубого правила особенно 
  опасна: в реальном SOC это завалило бы очередь критических алертов 
  ложными срабатываниями на каждом домен-контроллере, где активно 
  используется PowerShell
- Массовое срабатывание (~60 копий 92217 за секунды) при обычной 
  административной активности показывает, как легко подобное правило 
  создаёт перегрузку алертов

## 7. Рекомендации
- Добавить исключение в правило: исключить targetFilename, соответствующий 
  паттерну __PSScriptPolicyTest_*.ps1
- Понизить level для событий создания файлов в Temp без дополнительных 
  индикаторов (например, без последующего выполнения этого файла — 
  сопоставление с Sysmon Event ID 1 для того же processGuid)
- Это пример, почему слепое доверие дашборду/level опасно: правило с 
  level 15 на деле оказалось шумным, тогда как действительно критичное 
  92657 (разбор №2) имело level всего 6
