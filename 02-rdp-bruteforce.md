## 02-rdp-bruteforce.md

## 1. Метаданные
| Поле                 | Значение                                                     |
| -------------------- | ------------------------------------------------------------ |
| Дата                 | 2026-11-01                                                   |
| Техника ATT&CK       | T1110                                                        |
| Подтехника           | T1110.001 (Password Guessing), T1110.003 (Password Spraying) |
| Тактика              | Credential Access, Lateral Movement                          |
| Инструмент атаки     | Hydra                                                        |
| Источник (атакующий) | 10.10.10.102 (Kali)                                          |
| Цель                 | win-cl01 (10.10.10.101), Windows 11                          |
| Источник логов       | sysmon, Wazuh agent                                          |

## 2. Хронология (таймлайн)

| Время    | Событие                                                               | rule.id | rule.level | Источник    |
| -------- | --------------------------------------------------------------------- | ------- | ---------- | ----------- |
| 02:25:39 | Logon Failure - неуспешная попытка аутентификации                     | 60122   | 5          | Wazuh alert |
| 02:25:47 | Множественные неудачные попытки входа Multiple Windows Logon Failures | 60204   | 10         | Wazuh alert |
| 02:26:20 | Successful remote Logon detected - Успешное прохождение авторизации   | 92657   | 6          | Wazuh alert |
| 02:26:21 | Успешный вход был оборван выходом из сессии                           | 60137   | 3          | Wazuh alert |
Примечание: интервал между 92657 и 60137 (~1 сек) соответствует поведению Hydra, которая закрывает соединение сразу после подтверждения валидности пары логин/пароль, не инициируя полноценную рабочую сессию.
## 3. Обнаружение (Detection)
- **rule.id 60122** (level 5) — отдельные неудачные попытки входа с указанием Logon Failure, системой слишком широко помечается как T1531 Impact
- **rule.id 60204** (level 10) — Multiple Windows Logon Failures, срабатывает по `if_matched_sid 60122`, порог: 8 попыток за 120 секунд с одного source IP, помечает тактику T1110 Credential Access, техника Brute Force
- **rule.id 92657** (level 6) — Успешный вход пользователя после серии неверных попыток входа, показывает что атака прошла успешно и система может быть скомпрометирована, T1550.002, T1078.002, T1021.001. Тактики: Defense evasion, Lateral Movement, Persistence, Privilege escalation, Initial access. Техники: Pass the hash, Domain Accounts, Remote Desktop Protocol
- **rule.id 60137** (level 3) — "Windows User Logoff ", фиксирует выход из сессии после успешной аутентификации, поскольку Hydra лишь проверяет возможность входа, не продолжая процесс

## 4. Реагирование (Response)
- Active Response не настраивался для данной атаки: решение принято с учётом опыта разбора №1 (SSH), где Active Response не сработал из-за предполагаемого дефекта в Wazuh 4.14.9-rc2.

## 5. Оценка (Verdict)
**True Positive.** Подтверждено прямым сопоставлением алертов Wazuh с сырыми записями sysmon на win-cl01; успешный вход asidorova после серии неудач с того же IP — явный индикатор компрометации учётной записи.

## 6. Находки (Findings)
- Правило 60122 слишком широко классифицирует T1531, что создаёт слепую зону при атаке на существующие учётные записи
- Правило 92657 точно определило Успешную авторизацию, хотя при таком количестве неверных попыток с привязкой к 5 техникам (T1550.002, T1078.002, T1021.001) и 5 тактикам поставило лишь уровень опасности 6, стоит пересмотреть severity этого правила локально или не полагаться только на level при настройке оповещений.
- Базовое правило успешного выхода (60137 или аналог) не несёт MITRE-контекста, тогда как специализированное правило 92657 (pass-the-hash detection) даёт точную и полезную информацию — подтверждает, что для осмысленного приоритета алертов нужно смотреть не только на факт совпадения, но и на специфичность правила

## 7. Рекомендации
- Где возможно, установить обязательную MFA
- Рекомендуется приоритизировать алерты вроде 92657 (pass-the-hash detection) в первую очередь при триаже, так как они несут готовую атрибутику техники и явно указывают на компрометацию, а не просто на попытку атаки
- Создавать достаточно сильные пароли согласно путеводителю от NIST
- Пересмотреть или локально переопределить level для правила 92657, учитывая его критичность, либо настроить отдельное оповещение по MITRE-технике, а не только по level
